Mailstack — Animation & Design Reference

The stock library of Mailstack's animations + the living UI design reference. Tell the agent “Use the bubble animation from reference.html” (or the fade, or any section below) and it reproduces the specs here — no re-explaining from scratch.

Maintenance rule — When a component changes in the app, update the Design Reference section below to match. When a component is removed from the app, remove it from the Design Reference too. But never remove an animation section — even if the button that used it is gone. Animations take a long time to make; they stay as permanent reference. 1   Bubble Animation with the Flow

The bottom navigation's sliding pill. One pill, five tabs. Tap any tab — the pill flies there with a jelly squash-and-stretch, then settles with a tiny wobble. Try it: click the tabs below.

How it works — step by step (scribbled notes)

1

One pill, mounted once above the screens. It never unmounts — that is why it can travel instead of snapping. If each screen owned its own pill, it would just blink. ← keep it hoisted!

2

Tap a tab → the pill gets a new target: that tab's centre. The pill is 64 × 32, the two edges are animated separately — that is the whole trick.

3

Leading edge spring = stiff (550). Trailing edge spring = soft (300). Damping 0.70. The stiff edge pulls ahead → the pill stretches. The soft edge lags → the pill looks like jelly. ← stretch = jelly!

4

While stretched, the pill squashes a little vertically (squash & stretch, like a cartoon). When the trailing edge catches up, the pill relaxes back to 64 × 32.

5

Settle = a tiny wobble (the springs overshoot a hair, then rest). Total travel ≈ 350 ms. The page slide + the top-bar pill run on the same 350 ms, so everything lands together. ← sync matters!

6

The selected tab's icon sits ON the pill (white on violet). The other icons stay muted. No square ripple — the pill is the only tap feedback. ← pill only, no square!

Exact specs (for the agent)

WhatSpec
Pill size64 × 32 dp, fully rounded (16 dp radius), violet #5238E8
Bar80 dp content height + system-nav inset outside it; icons 24 dp; tonal elevation 0
Leading-edge springstiffness 550, damping ratio 0.70
Trailing-edge springstiffness 300, damping ratio 0.70
Squashvertical squash proportional to stretch, relaxes as edges meet
Settlesprings overshoot slightly → tiny wobble → rest at 64 × 32
Hoistingone bar instance above the NavHost; per-screen bars would snap, never slide
Tap feedbackpill only — tap indication = null (no square ripple)

How it works — step by step (scribbled notes)

1

The list is a normal scrolling list. On top of it we lay a fade mask — a gradient that goes transparent → opaque over a short band at each edge. The content itself does not change; only its visibility at the edges does.

2

Fade band = 28 dp, and subtle. Not a big dramatic fade — just enough that a row dissolves instead of getting sliced. ← small = classy!

3

Top edge fades ONLY once you have scrolled down (there is content above). Bottom edge fades ONLY while there is content below. At the very top / very bottom → no fade, rows fully visible. ← no fade for nothing!

4

Same fade on top AND bottom — mirrored. It is a scroll effect, not a decoration: it moves with the scroll, it never sits on content that is not moving.

3   Search-Pill Reshape — Hamburger Slides In from the Left

When you switch to the Mail tab, the hamburger (the three lines) slides in from the left edge and the search pill shrinks rightward to make room. When you leave Mail, the hamburger slides back out to the left and the pill expands again. The pill itself never enters from the right — its left edge is pushed by the hamburger. How it works — step by step (scribbled notes)

1

One bar, hoisted above the screens — same trick as the bubble. It never remounts, so the pill can reshape instead of snapping.

2

Only Mail has the hamburger. Its width animates 0 ↔ 48dp. The icon inside is offset by (width − 48dp), so it slides in from the left edge as the box grows. ← from the left!

3

The pill is weight 1f — it fills whatever width is left. As the hamburger grows, the pill's left edge is pushed rightward. The pill never enters from the right. ← pushed, not entering!

4

Leaving Mail is the exact reverse: hamburger slides back out to the left, pill expands. Same 350ms FastOutSlowIn — it lands together with the bubble + the page slide. ← sync matters!

5

The pill is the SAME field on every tab. On Mail it filters the mailbox in place; on other tabs it holds a local query and opens the Search screen on submit. The trailing actions swap with a short fade.

6

16dp edge margin, both sides — the pill (and the hamburger) never touch the screen edges. The old bar was a Material3 TopAppBar, which carries this inset itself. ← never edge-to-edge!

Exact specs (for the agent)

WhatSpec
Hamburgerwidth animates 0 ↔ 48 dp; icon offset = (width − 48 dp), so it slides in from the left edge
Search pillweight 1f — fills the remaining width; left edge pushed by the hamburger; never enters from the right
Duration / easing350 ms, FastOutSlowIn — same as the bubble + the page slide, all three land together
Bar64 dp + status-bar inset, surface; 16 dp horizontal margin, both sides
Actionsswap with a short fade — Mail: refresh + account; other tabs: account + overflow menu

4   Directional Tab Slide — Content Enters from Its Tab's Side

When you switch tabs, the new tab's content slides in from the side that tab sits on: a tab to the right slides in from the right, a tab to the left slides in from the left. The old content slides out the opposite way. The slide is opaque — no fade, no scale — so there is never a white flash. Try it: jump between the tabs below, in both directions.

How it works — step by step (scribbled notes)

1

A tab switch is a slide: the incoming screen slides in, the outgoing slides out — same motion, opposite directions.

2

Direction = where the target tab sits. Target to the RIGHT → new content enters from the right. Target to the LEFT → enters from the left. ← direction = tab position!

3

The slide is opaque — no fade, no scale. The old fade-through left a gap where both screens were see-through, and the window background showed as a white flash. Opaque = no gap, no flash. ← opaque kills the flash!

4

350ms FastOutSlowIn — the same 350ms as the bubble + the pill reshape, so all three land together.

5

Pushed routes (thread, settings, …) do NOT use this slide — they keep the fade-through. The slide is only for primary-tab switches.

6

Tab state is preserved (save/restore) — the slide never reloads a tab. It only moves what is already there.

Exact specs (for the agent)

WhatSpec
SlideslideInHorizontally + slideOutHorizontally, 350 ms, FastOutSlowIn
Directiontarget tab right of source → incoming enters from the right (offset +width), outgoing exits left; target left → mirrored
Opacityopaque — no fade, no scale. Never a gap, never a white/gray flash
Syncsame 350 ms as the bubble (§1) + the pill reshape (§3) — all three land together
Pushed routeskeep fade-through: exit 200 ms, enter 350 ms after a 120 ms delay, scale 0.97 → 1.0
Statetab switches use saveState/restoreState — loaded data, scroll position, ViewModels survive; nothing reloads

5   Design Reference — the whole UI, in one place

Keep this section updated. When a component changes in the app, change it here. When a component is removed from the app, remove it here. (Animations above are exempt — they stay forever.)

What Mailstack is

Mailstack is a Gmail-first mail organizer (Android, Kotlin + Compose, Material Design 3, strictly). Package com.greninjaop.mailorganizer. Five primary tabs — Home, Mail, Categories, Companies, Actions — plus pushed routes (thread, search, settings, …). Gmail is the source of truth; everything is local-first and account-isolated.

Layout — one screen, three layers

Chrome (top bar + bottom bar) stays put; only the content slides. That is why the pill animations can be continuous.

Rules that never change

  • Strict Material Design 3 on every UI change — no custom-styled lookalikes.
  • No app-created emojis in UI copy, fixtures, prompts, or generated text. Only emojis that arrived inside real mail content render.
  • No splash animation, Breeze artwork, photo backgrounds, or glass UI.
  • Preserve tab state, loaded data, scroll position, account isolation, navigation state, and edge-to-edge behaviour.
  • Never claim on-device verification from the sandbox — the phone is the only proof.

6   Scroll-Hide Bars — Top Slides Up, Bottom Slides Down

When you scroll down through the mail list, the top bar (search + everything) and the bottom bar both slide out of view, so the whole screen becomes just your emails. When you scroll up, both slide back into their exact places. The hide is a pure slide — no fade, opacity never changes. Try it: scroll the list below down, then back up.

How it works — step by step (scribbled notes)

1

Scroll DOWN through the list → both bars hide. Scroll UP → both bars show. That is the whole trigger — scroll direction, nothing else.

2

Hide = pure slide, no fade. Opacity never changes. The top bar translates UP out of view; the bottom bar translates DOWN out of view. ← slide only, no fade!

3

Show = the exact reverse. Top slides back DOWN in; bottom slides back UP in. Both return to the exact static positions they had. ← reverse = back to place!

4

Speed profiles are OPPOSITE per direction. Show: starts really slowly, then comes up fast, then lands gently (FastOutSlowIn). Hide: the opposite — starts fast, ends slow (LinearOutSlowIn). ← opposite speeds!

5

No spring, no overshoot, no wobble, no shake — a pure tween. The bubble gets the jelly; the bars get clean glides.

6

The list expands to fill the space when the bars hide. At the very top of the list (scroll = 0) the bars always show — you are never left without the search bar at the top.

Exact specs (for the agent)

WhatSpec
Triggerscroll down → hide both bars; scroll up → show both bars; at scroll position 0 → bars always shown
Motiontranslate only — opacity never changes (no fade). Top bar: 0 → −100% (up, out). Bottom bar: 0 → +100% (down, out). Show = exact reverse.
Show easingFastOutSlowIn — starts really slowly, then comes up fast, then lands gently in place. 250 ms.
Hide easingLinearOutSlowIn — the opposite speed profile: starts fast, ends slow. 250 ms.
Feelpure tween — no spring, no overshoot, no wobble, no shake
Listexpands to fill the freed space when the bars hide; shrinks back when they show
Wherescrolling primary content — the mail list (and any screen with a scrolling list under these bars)
